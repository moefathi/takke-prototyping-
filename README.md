# TAKKE – Prototyping

## Project Overview
In this project, I worked on prototyping TAKKE, a website that offers paid sound engineering courses for beginners and professional sound engineers. The main goal was to create a website that provides a learning experience for people who want to start their journey in sound engineering or improve their existing skills in sound production, mixing, and mastering.

I started by identifying the target users and understanding their needs through user categorization, classification, and behaviour modelling techniques. After that, I selected a suitable prototyping methodology and planned the tools and evaluation methods that I would use throughout the project.

## Target Users
I identified three main categories of users for TAKKE:

- **Beginners:** People who are interested in starting a career in sound engineering.
- **Junior and Senior Sound Engineers:** People who already work in sound engineering and want to improve their sound production, mixing, and mastering skills.
- **Professional Sound Engineers:** Experienced sound engineers who want to develop more advanced skills.

I also used user classification techniques such as segmentation, user personas, and the value proposition canvas, along with BJ Fogg's behaviour model.

## Prototyping Methodology
I selected the Rapid Throwaway Prototyping methodology because the requirements were not completely clear at the beginning of the project. This methodology allowed me to create prototypes, collect feedback, make changes, and repeat the process before developing the final high-fidelity prototype.

I followed this approach across three stages: low-fidelity wireframes, mid-fidelity mockups, and a high-fidelity prototype.

## Tools Used
- **Figma:** Used to create the low-fidelity wireframes, mid-fidelity mockups, and high-fidelity interactive prototype.
- **Google Forms:** Used to create surveys and collect feedback from users during the iterations.
- **Ready-to-use Templates:** Used to create user classification techniques and behaviour modelling.

## Low-Fidelity Prototype
I created the initial wireframes and used two survey iterations to collect feedback about the overall layout, element positions, navigation, and number of pages.

In the first iteration, users highlighted that the cart in the navigation bar was not clear, so I changed its position and layout. In the second iteration, I collected further feedback and identified improvements needed for the course material page, footer size, and Enroll Now button.

[View Low-Fidelity Prototype](https://www.figma.com/proto/hsEuNFuPlbPeqzjISd1IVu/Takke?node-id=167-7343&t=e4b7rzw4CAyfN3re-1)

## Mid-Fidelity Prototype
For the mid-fidelity mockups, I created two designs for each page and used A/B testing to compare them and identify which designs users preferred.

The feedback showed that users preferred the original design for the home, signup, signin, and update profile pages, while they preferred the alternative design for the cart and My Courses pages.

After applying the selected designs, I conducted unmoderated usability testing by sharing the mockup with users and collecting their feedback. Most users were satisfied with the design and found the website easy to navigate.

[View Mid-Fidelity Prototype](https://www.figma.com/proto/hsEuNFuPlbPeqzjISd1IVu/Takke?node-id=178-964&t=e4b7rzw4CAyfN3re-1)

## High-Fidelity Prototype
In the high-fidelity stage, I added interactions and functionality to make the prototype closer to the final website. These included:

- Page navigation and links between pages.
- Dissolve transitions with ease-out animation.
- Smooth scrolling for the main call-to-action button.
- Interactive buttons and hover effects.
- Interactive checkboxes.
- Interactive navigation bar.
- Simulated add-to-cart process.
- Interactive input fields.

The cart process was simulated using Figma variants. It was not fully connected to the available courses because the prototype did not use a database.

The final high-fidelity prototype is presented through a video walkthrough demonstrating its design and interactions.

[Watch High-Fidelity Prototype Walkthrough](https://youtu.be/-wu0ib15pyA)

## User Feedback and Evaluation
I used different evaluation methods throughout the project:

- **Surveys:** Used during both low-fidelity iterations to collect feedback about the wireframes.
- **A/B Testing:** Used during the first mid-fidelity iteration to compare alternative designs.
- **Unmoderated Usability Testing:** Used during the second mid-fidelity iteration to evaluate the mockups and collect users' opinions before moving to the high-fidelity stage.

The feedback helped me identify issues that I had not considered in the original plan and improve the design based on actual user preferences.
